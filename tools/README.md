# tools

## gen-commands.py: the console command reference

`content/docs/commands/` (except `_index.de.md`) is generated from the console grammar of the
Onesimus Director. Do not edit those pages by hand; change the grammar in the Director and
regenerate. Python 3, standard library only.

1. Get the grammar, either
   - from a running Onesimus Director: in API mode 2 the command `.grammar` prints it as JSON
     (`{"grammar": {"schema": 1, "commands": [...]}}`), e.g. type `.api 2` and then `.grammar`
     in `oconsole` and save the JSON reply to a file, or
   - from the copy in the onesimus-dird repository: `docs/wiki/commands/console-grammar.json`.
2. Regenerate:

   ```sh
   tools/gen-commands.py path/to/console-grammar.json
   ```

   Without an argument the script reads `~/.cache/onesimus-agents/website/console-grammar.json`.
   `--out DIR` writes somewhere else than `content/docs/commands/`.
3. Check with `hugo --gc --minify -d /tmp/site-check` and commit the changed pages.

The output is deterministic: an unchanged grammar changes no file. Pages of commands that are
no longer in the grammar are deleted (only files carrying the "generated by" marker).
References to unknown commands (see also, value sources) are printed as warnings.

The configure pages link every `configure add|update <type>` argument to the configuration
reference and replace the grammar's placeholder texts ("Directive (string)") with the first
sentence of the directive description from `data/config/` (`--config-data ''` turns that off).

## gen-config.py: the configuration reference

`content/docs/config/` (except `_index.de.md`) is generated from `data/config/<resource>.json`:

```sh
tools/gen-config.py                      # from data/config/*.json
tools/gen-config.py --grammar g.json     # from odir's .grammar once it carries the texts
```

With `--grammar` the directive texts are taken from the `configure add <type>` arguments of the
grammar (`long`, `examples`); resource types whose arguments still have placeholder descriptions,
and the nested blocks, come from `data/config/`.

### data/config/<resource>.json (hand-over format, schema 1)

One JSON object per resource type (director, client, job, jobdefs, storage, catalog, schedule,
fileset, pool, messages, counter, profile, console, user). UTF-8, neutral English text without
Markdown, so the Director (`.grammar`) and the GUI (editor tooltips) can use it as it is.

```json
{
  "schema": 1,
  "resource": "Pool",                 // resource name in the configuration
  "key": "pool",                      // lowercase, as in "configure add pool"
  "source": "...",                    // where types and defaults come from
  "description": "...",               // what the resource is for
  "examples": [ { "title": "...", "config": "Pool {\n ...\n}", "explanation": "..." } ],
  "directives": [
    {
      "name": "Volume Retention",     // canonical spelling as in the Bareos documentation
      "key": "volumeretention",       // console key: lowercase, no spaces (grammar argument name)
      "aliases": [],                  // other accepted names (canonical spelling)
      "type": "time",                 // name, string, path, resource, resource list, yes|no,
                                      // positive integer, integer, time, size, speed, password,
                                      // ACL list, message destination, enum, block, ...
      "default": "31536000",          // as in the Director's item table (time in seconds), or null
      "values": [],                   // valid values for enum and yes|no
      "required": false,
      "deprecated": false,
      "onesimus": false,              // true: Onesimus extension, unknown to Bareos
      "description": "...",           // 2 to 6 sentences: effect, use, pitfalls, units
      "examples": [ { "config": "Pool {\n  Name = Full\n  Volume Retention = 1 year\n}",
                      "console": "configure add pool name=Full volumeretention=\"1 year\"",
                      "explanation": "..." } ]   // console and explanation are optional
    }
  ],
  "blocks": [                         // nested syntax: FileSet Include/Exclude/Options,
    { "name": "Options", "key": "options", "description": "...",   // Schedule Run, Job RunScript,
      "directives": [ /* same objects as above */ ] }              // Messages message types
  ]
}
```

Types, defaults, `required`, `deprecated` and aliases follow the Director's item tables
(onesimus-dird `crates/odir/src/commands/show_items.rs`, generated from Bareos 25.1.2) plus the
Onesimus extensions accepted by `crates/odir/src/config_check.rs`.
